# OhioT1DM 与本地 CGM 报告接入

本批仅接入本地研究预览，不发布线上、数据文件、报告或任何患者记录，不调用外部 AI。
用户提供的 OhioT1DM 2018/2020 XML：12 名匿名受试者，train/test 文件均保留来源及 SHA256。
依据原论文 https://ceur-ws.org/Vol-2675/paper11.pdf ：约 5 分钟 CGM、bolus、basal、temp_basal 和 meal。
日期为 day-month-year，已由原数据集脱敏平移，可能在未来；保留原日期、不平移为今天。
原时区未给出，UTC 仅为存储约定，页面按浏览器时区显示。weight=99 是占位值，绝不写入体重。

CGM 写入现有只读来源 ohio_cgm；指尖血糖作为独立事件，不和 CGM 混合计算或连线。
基础输注率 U/h、临时基础率 U/h、追加剂量 U、饮食碳水 g 分轨显示。
常规基础率延续至下一条，临时基础率在其起止区间覆盖常规值，0 表示暂停。
页面不把基础率与剂量相加，不根据这些记录计算用药建议；扩展 bolus 保留原起止时间和类型。
训练/测试集重复边界使用稳定 UUID 去重；同一时间冲突的 CGM 值直接拒绝。非有限值、负值、倒置区间、超出系统血糖范围的行进入拒绝清单。
其他 XML 传感器、睡眠和事件尚未转换，原 XML 保留。不能把研究传感器伪装为患者的 Zepp 观测。

CGM 仅连接间隔不超过15分钟的同来源点，不填补缺测；每次接口最多返回5000个血糖点，明确标注截断。
选择研究样本后自动定位数据最新一天，避免默认当前日期为空；可手工选择最多90天。
事件按相同范围筛选，包含跨入所选范围的基础率或区间事件。图最多1000条、表末尾100条，明确展示总数和截断。
所有研究元数据和事件经既有医护授权或个人绑定的全部患者解锁检查后返回，保留访问审计。

CGM 目录中数字命名的20份PDF为用户提供的医院葡萄糖评估报告（并非都为1型糖尿病）。
本地离线用 pypdf 提取第一页原报告的监测日期、平均葡萄糖、标准差、CV 和估算HbA1c，并保留原始单位、文件名及SHA256。
原报告姓名、电话、设备编号不入库；不反推AGP或每日图中的逐点采样；不把估算HbA1c冒充化验值。
摘要在独立“CGM报告样本”账号展示，无原始点时血糖曲线明确为空；报告摘要对应整个监测期，不随所选一天重新计算。
两份论文PDF不是患者报告，不作为报告样本导入。PDF继续保留在用户原目录，前端不提供原始报告下载。

默认不写入；导入前备份，失败按单个受试者回滚。可重复运行，新增行数应为0；既有来源变化则拒绝覆盖。
