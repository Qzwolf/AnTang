# 两稿比对的小集子

这一套测的是「第二稿有没有偷偷改数字」，不是模型写得好不好。

## 它守的是什么

主动关怀里，带数字的稿子会先写一稿，再让同一个模型写第二稿只改措辞。
两稿的数字集合必须一致，否则退回第一稿（`refine_wording`），连改两次都不行就
不发第二稿。这个集子就是那条防线的回归测试。

## 跑法

```bash
cd api
python -m evals.two_draft.runner          # 只看错的和汇总
python -m evals.two_draft.runner --verbose
```

两个指标必须都是 1.0：`agreement`（判对的条数占比）、`blocked_rate`（该拦下的
有没有漏放）。漏放一次改过数字的稿子，等于让他看到一句我们没核对过的话。

## 边界（写在集子里，免得以后误以为它管得更宽）

- 它只认阿拉伯数字。中文数字（「一型」「两次」「半支」）不在它的视野里，
  `hidden-digit-in-word` 这条就是把这个缺口钉在明处。
- 单位换了但数字没换算（`3.2 mmol/L` → `58 mg/dL`）会被拦下，因为数字集合变了。
  这是对的：这一关宁可多拦。
- 没有数字的句子它一律放行，哪怕第二稿多了一句安慰的话
  （`extra-note-no-number`）。语气不是这一关的事。

## 还没做

- 这些句子是自己写的，不是真实对话里捞的。真跑起来以后，应该从线上抽取
  「第一稿被退回」的样本补进来。
- 只比数字集合，不比顺序、不比绑定（「早 6.4 / 晚 9.1」对调成「早 9.1 / 晚 6.4」
  数字集合一样，这一关放行）。要抓这种得比对数字与它修饰的对象，那是下一步。
